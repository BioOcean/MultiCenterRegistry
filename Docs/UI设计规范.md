# UI设计规范

生成时间：2026-06-04

## 参考对象

参考项目：`F:\project\BCAgent`。

本系统采用 BCAgent 的浅色工作台布局节奏，但视觉上统一为更简洁的现代后台风格：白底面板、弱边框、轻阴影、蓝色主按钮、紧凑表格和明确操作区。MCR 不照搬页面内容，只复用页面层级、间距和操作组织方式。

## 布局

### 顶栏

- 左侧为品牌块：图标方块、系统名称、模块说明。
- 右侧为用户信息和退出区。
- 顶栏使用简洁浅色背景、底部分隔线和轻阴影。
- 不再使用居中标题，避免长系统名称挤压右侧用户信息。

### 左侧菜单

- 使用浅色侧栏，宽度 200px。
- 顶部显示“工作台 / 功能菜单”。
- 菜单项使用透明底，选中/悬停为浅蓝底和蓝色文字。
- 不使用深绿色大色块，降低后台维护页压迫感。

### 右侧内容区

- 页面最外层保留 14px 间距。
- 页面头部使用白底面板：标题、副标题和右侧操作按钮。
- 列表、筛选、预览都用统一白底面板样式。
- 新增、编辑、配置类操作统一使用弹窗，不在列表页中间展开编辑表单。
- 列表面板底部必须有分页条；顶部工具条只放业务操作、批量选择提示或必要说明，不重复展示“共多少/每页多少”。
- 筛选面板优先一行网格布局：筛选框、下拉框、查询和重置按钮同一行底部对齐；窄屏才换成单列。
- 列表面板内部不再额外套大内边距，表头、表体和分页条直接贴合面板边界。

### 筛选控件高度经验

- MudBlazor 的 `Outlined + Dense` 输入框高度不能只改 `.mud-input-root`，否则外层容器、outlined 边框、输入槽、图标区和 label 仍可能按默认高度撑开。
- 筛选区确认可用做法：在页面筛选面板作用域内同时约束 `.mud-input-control`、`.mud-input-control-input-container`、`.mud-input`、`.mud-input-root`、`.mud-select-input`、`.mud-input-adornment`、`.mud-input-outlined-border` 和 `.mud-input-label-outlined`。
- 标准目标高度：筛选框整体 40px，内部输入槽 38px，查询/重置按钮 40px，并保持同一行底部对齐。
- 同类页面后续直接复用这套高度链路，不再通过按钮下移或局部 margin 反复修补。

### 样式作用域经验

- Blazor CSS isolation 会给当前 `.razor` 文件直接渲染的 HTML 增加作用域属性；父组件 `.razor.css` 的普通选择器不能命中子组件内部 HTML。
- 父组件需要控制子组件内部元素时，必须以父组件实际渲染的外层节点为锚点使用 `::deep`，例如 `.case-edit-dialog ::deep .case-dialog-head`；不能只写 `.case-dialog-head`。
- MudBlazor 组件通过 `Class` 参数传入的类可能落在组件内部生成的 HTML 上，该 HTML 不一定带当前组件的 CSS isolation 作用域属性；需要参与 grid 跨列、宽度或定位时，优先用当前组件自己渲染的 `<div class="...">` 包一层承载布局类。
- Blazor `InputFile` 生成的原生文件控件也按子组件处理；自定义上传按钮必须用外层按钮/label 承载视觉样式，并通过 `.上传按钮 ::deep .file-input` 隐藏原生控件，避免显示“选择文件/未选择文件”。
- 页面专属弹窗不必默认放到 `app.css`。只有跨多个页面复用的通用控件样式放全局；单页面样式保留在页面 CSS，但跨父子组件时必须按上一条使用 `::deep`。

### 质控管理员页面细节

- 页面间距：主内容区使用 12px 纵向间距，面板内边距以 14px/16px 为基准。
- 筛选区：多个筛选项和查询、重置按钮保持同一行底部对齐；窄屏再换行。
- 列表区：使用浅灰表头、弱分隔线和浅灰 hover；列表顶部只保留必要标题和提示，分页固定在底部。
- 分页区：统一复用 `admin/users` 的页码式分页。结构为 `.pager` 内放 `.pager-total`、`.pager-pages`、`.pager-summary`；页码超过 7 页时显示首尾页和省略号；业务批量按钮如“批量更换术者”可放在分页条最左侧，但分页控件本身不改结构。
- 操作区：新增、导出、刷新等按钮放在页面头部右侧；行内操作使用文字按钮，避免重色块。
- 弹窗区：新增和编辑类操作统一使用白底弹窗，输入区与弹窗边框保持至少 20px 左右间距。
- 新建病例弹窗：医院和手术类别独占一行，其余字段一行两列；字段统一使用“左侧标题、右侧控件”的横向表单行，不使用 MudBlazor 内置 `Label`；必填项在标题前显示红色 `*`；输入框、下拉框、日期控件和 tag 均按同一横向结构排列；仅性别、手术类别使用 tag 选择，其余选择题使用下拉框；情况/原因说明选择“其他”时显示“补充说明”textarea，独占一行。
- 会议列表页：功能和交互参考旧系统 `reviewMeetingSeachTable.vue`，采用“筛选区 + 待评审/已结束切换 + 新建会议 + 单列会议卡片”的组织方式；按钮权限和状态条件沿用旧系统，会议编辑弹窗使用“专家多选后再选组长”的联动逻辑，不再输入专家用户 ID。
- 病例详情页：不展示“创建病例信息”这类新建病例辅助模板；只展示疾病病例表单本身。前置题未选择或未满足条件时，受控题直接隐藏，不用已有迁移值强行展示。左侧目录点击后定位到右侧目录标题行。文件上传题初始只显示“上传图片”按钮；有附件后左侧显示首张图片或文件入口，右侧显示备注 textarea 和重新上传按钮。
- 详情表单视觉：参考 `F:\project\Bio.FormSetLib` 的表单样式，使用白底细边框卡片、简洁章节标题栏、题目标题在控件上方、题目块按列流式排布；题目前不加编号，已有值可用小勾选图标提示。左侧目录项需有明确的项边界、左侧状态线和题目数量徽标，便于区分不同目录；上传按钮采用紧凑尺寸，不应高于或重于题目标题。禁止在章节、题目、控件区反复叠加浅灰底、渐变底、蓝色淡底和卡片背景，避免页面显脏。
- 日期题必须使用日期控件；空值日期控件需要隐藏浏览器默认的 `yyyy/mm/dd`、`yyyy/mm/日` 等占位文本，不能让占位内容误导为实际答案。
- 病例详情/编辑页和专家评价编辑页不显示系统左侧功能菜单，保留顶部 Header，正文使用全宽内容区承载表单。

## 后台页面细节

- 筛选区：参照 BCAgent `patients-filter-grid`，使用 `grid-template-columns` 固定多个控件一行排列。
- 筛选输入框：MudBlazor `Outlined + Dense` 需要按“筛选控件高度经验”完整约束高度链路，避免只改内层导致筛选框偏高。
- 操作按钮：高度 40px，查询为主按钮，重置/新增/刷新为描边按钮。
- 弹窗区：新增、编辑、配置全部使用弹窗；弹窗遮罩为深灰半透明，弹窗为白底、浅灰边框和轻阴影。
- 列表区：表头浅灰底，行高紧凑但保留 13-14px 内边距，hover 使用浅灰底，不使用大面积渐变。
- 分页区：固定在列表面板底部，使用浅灰底和顶部边线；统一显示总数、页码按钮和页摘要，不再只保留上一页/下一页。

## 后续统一规则

1. 病例、质控、会议、随访、统计、后台内容等页面继续复用同一顶栏、菜单和背景。
2. 列表页统一使用：页面头部、筛选面板、列表面板、底部分页条。
3. 详情页统一使用：页面头部、摘要面板、操作条、主体表单面板。
4. 不新增卡片入口页；登录后仍按角色直接进入默认业务页面。
5. 新增、编辑、配置类操作只走弹窗，不再维护 `/new`、`/edit` 这类独立页面路由。
6. 不做多语言和面板设置。
7. Header、左侧菜单、右侧正文外壳等框架布局写在 `wwwroot/app.css` 的布局层；MudBlazor 框架组件不再依赖 CSS 隔离样式命中。
8. 输入框、按钮、筛选区、列表、表格、分页、弹窗、状态标签等通用控件样式只写在 `wwwroot/app.css`。
9. 组件同名 `.razor.css` 只保留本页特有布局、列宽、卡片或表单差异。
10. 禁止在文件末尾追加“最终覆盖”类规则；发现重复公共选择器时应清理原规则，而不是用更高优先级覆盖。
11. 页面和弹窗不放说明性段落、操作说明或大段引导文字；通过字段显隐、必填标识、状态、按钮禁用和校验提示引导用户。
12. 所有新增 UI 必须先对照本文件，沿用已确认页面的布局、间距、弹窗、按钮、筛选、列表和分页规范。
